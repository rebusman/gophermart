# Миграции схемы PostgreSQL

Каталог содержит версионированные SQL-миграции, встраиваемые в бинарник
сервиса и применяемые при старте до открытия HTTP-порта.

## Соглашения

Имена файлов следуют формату `golang-migrate`:

```text
{версия}_{название}.up.sql
{версия}_{название}.down.sql
```

Версия — шесть цифр с ведущими нулями, название — краткое описание в
`snake_case`. Каждая миграция состоит из пары файлов: `up` применяет
изменение, `down` его откатывает.

## Правила

- **Каждая функциональная возможность приносит собственную миграцию.** Схема не
  создаётся одним `init`-файлом.
- **Уже применённая миграция не изменяется.** Любая правка схемы оформляется
  новой парой файлов с большей версией.
- **Порядок версий определяется внешними ключами** между таблицами и совпадает
  с порядком реализации возможностей.

## Планируемый порядок

```text
users
  ├── balances        создаётся вместе с users: регистрация заводит
  │                   пользователя и его пустой счёт в одной транзакции
  ├── orders
  │     └── ALTER: + attempts, next_attempt_at (расписание повторов)
  └── withdrawals     ссылается только на users: номер заказа в списании
                      гипотетический и не обязан существовать среди заказов
```

Отдельной таблицы-журнала движений баллов в схеме нет. Каждое списание
полностью описано строкой `withdrawals`, каждое начисление — полем
`orders.accrual` вместе с финальным статусом заказа, а `balances` хранит
агрегат, изменяемый теми же операторами. Роль барьера от повторного изменения
счёта несут ограничения самих таблиц: у списания — первичный ключ
`(user_id, order_number)`, у начисления — условие перевода заказа в
непройденный финальный статус. Решение и его цена разобраны в
`openspec/changes/balance-withdrawals/design.md`.

## Текущее состояние

| Версия | Файл | Содержание |
|---|---|---|
| `000001` | `000001_users_balances` | Таблицы `users` и `balances` |
| `000002` | `000002_orders` | Таблица `orders` и индекс под выдачу списка заказов |
| `000003` | `000003_withdrawals` | Таблица `withdrawals` и индекс под выдачу истории списаний |

`balances` создаётся вместе с `users`, а не вместе со списаниями: регистрация
обязана заводить пользователя и его пустой счёт в одной транзакции, поэтому
счёт не может появиться отдельной миграцией позже.

## Ручное применение

Сервис применяет миграции сам. Для отладки схемы доступны команды:

```sh
make migrate-up      # применить все неприменённые миграции
make migrate-down    # откатить последнюю
```
